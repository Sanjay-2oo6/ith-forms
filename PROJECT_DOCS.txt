## PROJECT OVERVIEW
====================
Form builder + response collection app for InnoTech-Hub.
- Admins: Build and publish forms
- Public: Submit responses via public link
- Admins: Review, track statuses, export data (Excel, CSV)

## TECH STACK
=============
- Frontend: React 19 + TanStack Start/Router/Query
- Styling: Tailwind v4 (design tokens in src/styles.css)
- Backend: Supabase (Postgres + Auth + Storage)
- Validation: Zod
- Drag-Drop: @dnd-kit
- Excel Export: ExcelJS
- CSV Export: Custom implementation
- Error Tracking: Sentry (optional)
- Testing: Vitest + Playwright

## ARCHITECTURE
===============
- NO custom backend - browser talks directly to Supabase
- Admin: Authenticated session via RLS policies
- Public: Read forms via anon RLS, write via submit_response RPC only
- File uploads: Private submission-files bucket + register_submission_file RPC
- Security: SECURITY DEFINER RPCs, RLS policies, CSP headers
- Theme system: CSS custom properties, glassmorphism, dark/light modes

## SECURITY MODEL
=================
1. Supabase URL + ANON_KEY are PUBLIC by design ✅ SAFE
2. All security via RLS policies + SECURITY DEFINER RPCs
3. Public can ONLY call submit_response() RPC (no direct table writes)
4. Admin tables gated by is_admin() RLS policy
5. SERVICE_ROLE_KEY never exposed in frontend (server-only)
6. CSP headers enforce content security
7. Rate limiting prevents spam (5 submissions per minute per email)
8. Idempotency keys prevent duplicate submissions
9. File uploads validated (size, type, path sanitization)

### What Attackers CAN'T Do (Even with Supabase URL + Anon Key)
- ❌ Read other users' submissions
- ❌ Modify existing submissions
- ❌ Delete submissions
- ❌ Access admin data
- ❌ Bypass form limits or rate limits
- ❌ Submit invalid data (Zod + DB constraints)
- ❌ Access SERVICE_ROLE_KEY
- ❌ Bypass RLS policies

## AUTHENTICATION FLOW
======================
Admin Login:
1. Admin logs in via Google OAuth (admin/login page)
2. Supabase redirects to Google consent screen
3. Google redirects back to Supabase callback URL
4. Supabase validates code, creates session
5. App stores session in localStorage
6. Admin can now access admin routes

Public Forms:
1. Anonymous user opens form link
2. Form data loaded via anon RLS policy
3. Optional: Click "Sign in with Google" for verification
4. Session stored in sessionStorage (form-specific)
5. Submission includes verified_email if authenticated

## CONVENTIONS
==============
- Route components own state (no global state beyond TanStack Query)
- No Redux/Zustand - TanStack Query cache IS the state
- Query keys: ["form-meta", formId], ["responses-tabular", ...], ["option-map", formId]
- Debounced saves (600ms) in form builder
- All admin mutations → audit_logs row
- Toasts (sonner) for user-facing errors
- Comments explain WHY, not what
- Tailwind utilities only - no custom CSS (except design tokens in styles.css)

## THINGS THAT WILL BITE YOU
============================
- NEVER give anon users direct table write access (use RPCs only)
- CSP keeps 'unsafe-inline' WITHOUT nonce (with nonce breaks vite-plugin-react)
- forms.response_count is trigger-maintained (no manual updates needed)
- Reference IDs are per-form: {ABBR}-{form-prefix}-{00001}
- Choice answers store VALUES (map to labels via optionMap in exports)
- Checkbox multi-values use || delimiter (not comma, for CSV compatibility)
- Background images: Use contain (not cover) to show entire image
- Google OAuth: Supabase callback URL must be in Google Cloud authorized URIs

## TROUBLESHOOTING
==================
Common Issues:

1. "Function gen_random_bytes does not exist"
   → Use md5(gen_random_uuid()::text) instead
   → Migration 059 fixes this

2. "Column reference submission_count is ambiguous"
   → Qualify with table name: verified_emails.submission_count
   → Migration 059 fixes this

3. Google OAuth Error 400: redirect_uri_mismatch
   → Add callback URL to Google Cloud authorized URIs
   → Wait 5-10 minutes for Google cache to update

4. CSV/Excel export button not visible
   → Hard refresh browser (Ctrl+Shift+R)
   → Clear browser cache

5. Background image not showing entire PNG
   → Use background-size: contain (not cover)
   → Add background-repeat: no-repeat
